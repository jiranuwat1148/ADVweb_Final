**เริ่มใช้งาน**

Clone repository นี้ผ่าน GitHub Desktop แล้วเปิดโฟลเดอร์ `ADVweb_Final` ใน VS Code โดยต้องติดตั้ง Node.js ไว้ก่อน ซอร์ส Angular อยู่ที่ราก repository และยังไม่มี backend ที่รันได้

ทดสอบด้วย Node.js 24.18.0 และ npm 11.16.0 ใช้ Angular 22.2 และ TypeScript 6.0

เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน:

```sh
npm.cmd install
npm.cmd start
```

เปิด [http://127.0.0.1:4200](http://127.0.0.1:4200) หยุดเซิร์ฟเวอร์ด้วย `Ctrl+C`

คำสั่งด้านบนใช้สำหรับ Windows บน macOS/Linux ใช้ `npm` แทน `npm.cmd` ข้อมูลที่แก้ไขในเบราว์เซอร์เครื่องเดิมไม่ได้อยู่ใน repository เครื่องหรือเบราว์เซอร์ใหม่จะเริ่มด้วยข้อมูลตัวอย่าง

คำสั่งเพิ่มเติม:

```sh
npm run build   # สร้าง production build ใน dist/lunch-dispatch/browser
npm run check   # ตรวจ Angular และ TypeScript ด้วย development build
npm test        # ตรวจเงื่อนไขจัดเส้นทางและกติกาออเดอร์
```

ถ้าต้องการเปิด production build ให้รัน `npm run build` ก่อน แล้วรัน `node preview.cjs` และเปิด [http://127.0.0.1:8080](http://127.0.0.1:8080) ไฟล์ `dist` ถูกสร้างในเครื่องและไม่เก็บใน Git

**หน้าจอและสิ่งที่ทำได้**

| URL          | หน้าที่                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------- |
| `/`          | ภาพรวมออเดอร์ แผนที่เส้นสี ใบงาน ต้นทุน กำไร คำนวณทางเลือก เปรียบเทียบและเลือกแผน ยืนยันการจัดส่ง |
| `/orders`    | เพิ่ม แก้ไขจำนวน ยกเลิก ค้นหา กรองสถานะ และจำลองออเดอร์                                           |
| `/customers` | เพิ่ม แก้ไข ลบ ค้นหาลูกค้า ดูพิกัดบนแผนที่ และเปิดแอปนำทาง                                        |
| `/rider`     | กรอกเลขใบงาน ดูจำนวนกล่อง ลำดับจุดส่ง เบอร์โทร และปุ่มนำทาง                                       |

เริ่มต้นด้วยลูกค้าและออเดอร์จำลอง 24 รายการ รวม 48 กล่อง เมื่อเปิดภาพรวมครั้งแรก ระบบคำนวณแผนฉบับร่างให้ดู จากนั้นใช้ปุ่มคำนวณใหม่เพื่อดูทางเลือก หรือกดจำลองออเดอร์เพื่อเริ่มทดลองชุดใหม่

**วิธีทดลองครบหนึ่งรอบ**

1. เปิดหน้าออเดอร์ ลองแก้ไขจำนวนกล่องหรือเพิ่มออเดอร์
2. กลับหน้าภาพรวม ระบบเตรียมแผนฉบับร่างจากข้อมูลล่าสุด
3. กดใบงานไรเดอร์เพื่อเลือกเส้นทาง และตรวจลำดับจุดส่งด้านล่าง
4. กดคำนวณใหม่ แล้วเปิดรายการเปรียบเทียบแผน เลือกแผนที่ต้องการได้หากข้อมูลออเดอร์ยังเป็นชุดเดียวกัน
5. กดยืนยันแผนจัดส่ง อ่านสรุปแล้วกดยืนยันแผน ออเดอร์ของรอบนี้จะถูกล็อก
6. เลือกไรเดอร์ แล้วกดเปิดใบงานเพื่อดูหน้าเดียวกับที่ไรเดอร์ใช้ หรือคัดลอกเลขใบงานไปกรอกที่ `/rider`

**ข้อมูลจำลองและข้อจำกัด**

- ยังไม่เชื่อมต่อ backend ข้อมูลทั้งหมดเก็บด้วย `localStorage` ในเบราว์เซอร์
- เลขใบงานเปิดได้ในเบราว์เซอร์ที่มีชุดข้อมูลเดียวกันเท่านั้น การใช้จริงระหว่างเครื่องร้านกับมือถือไรเดอร์ต้องเชื่อมต่อฐานข้อมูลผ่าน backend
- หน้าร้านเป็นโหมดสาธิต ยังไม่มีระบบยืนยันตัวตนสำหรับเจ้าของร้าน
- แผนที่พื้นหลังใช้ Leaflet และ OpenStreetMap เมื่อโหลดออนไลน์ไม่ได้จะแสดงภาพแผนที่จำลอง
- เส้นจัดส่งเป็นการเชื่อมพิกัดตามลำดับ ระยะทางคำนวณด้วย Haversine × 1.25 จึงเป็นค่าประมาณ ไม่ใช่เส้นทางขับรถตามถนนจริง
- ปุ่มเปิดแผนที่ใช้ Google Maps เพื่อค้นหาเส้นทางจริงไปยังจุดส่งทีละจุด
- เวลาเดินทางใช้ความเร็ว 30 กม./ชม. เพิ่มเวลาส่งมอบ 2 นาทีต่อจุด และเผื่อเวลา 5 นาที
- ทุกไรเดอร์ออกพร้อมกัน 11:30 น. และแผนที่ยอมรับต้องส่งครบตามค่าประมาณไม่เกิน 12:25 น. เพื่อเผื่อก่อนกำหนด 12:30 น.
- นับระยะจากร้านถึงลูกค้าคนสุดท้าย ไม่รวมขากลับร้าน
- การคำนวณทางเลือกอาจได้ต้นทุนสูงขึ้นหรือคำตอบเดิม ให้เปรียบเทียบตัวเลขก่อนเลือก ระบบไม่ได้รับรองคำตอบที่ดีที่สุดทุกกรณี
- Google Fonts และแผนที่ออนไลน์ต้องใช้อินเทอร์เน็ต หากโหลดฟอนต์ไม่ได้เบราว์เซอร์จะใช้ฟอนต์สำรอง

หากต้องการเริ่มทดลองใหม่หลังยืนยันแผน ให้ลบคีย์ `lunch-dispatch-demo-v1` ใน localStorage ผ่าน Developer Tools แล้วรีเฟรชหน้า การลบคีย์นี้จะล้างข้อมูลจำลองที่แก้ไขไว้

**โครงสร้างโค้ด**

```text
src/
  main.ts                        # เริ่ม Angular และกำหนดเส้นทางหน้าเว็บ
  styles.css                     # ฟอนต์ สี และรูปแบบพื้นฐาน
  app/
    models.ts                    # ชนิดข้อมูลและค่าตั้งร้าน
    dispatch.store.ts            # ข้อมูลจำลอง CRUD และอัลกอริทึมจัดกลุ่ม
    workspace.component.ts       # การทำงานของหน้าจอ
    workspace.component.html     # เนื้อหาและฟอร์ม
    workspace.component.css      # รูปแบบหน้าจอและการแสดงผลบนมือถือ
    route-map.component.ts       # แผนที่และการเลือกเส้นทาง
    route-map.component.css      # รูปแบบแผนที่และหมุด
    icon.component.ts            # ไอคอน SVG
scripts/
  check-domain.mjs               # ตรวจเงื่อนไขของ planner และ store
```

**ต่อเข้ากับ backend**

เพิ่ม service ที่ใช้ Angular `HttpClient` แล้วเปลี่ยนการเรียก CRUD และ planner ใน `DispatchStore` ไปเรียก API ตามเอกสาร backend โดยยังคงชนิดข้อมูลของหน้าจอไว้ได้:

- ลูกค้า → `/api/customers`
- ออเดอร์ → `/api/orders`
- สร้างและเลือกแผน → `/api/plans`
- ยืนยันแผน → `/api/plans/:id/confirm`
- ค้นหาใบงาน → `/api/rider/jobs/lookup`

ย้ายการคำนวณต้นทุน การจัดเส้นทาง และการตรวจความถูกต้องไปที่ backend เพื่อให้ทุกเครื่องใช้ข้อมูลเดียวกัน และใช้ระยะทางถนนจริงสำหรับแผนที่ใช้งานจริง

**การตรวจที่ดำเนินการ**

- Production build และ Angular strict template compilation
- สูตรตัวอย่าง: 6 กล่อง × 2 กม. มีค่าส่งรวม 39 บาท
- ครอบคลุมออเดอร์ครบ ไม่มีงานซ้ำ และใบงานไม่เกิน 3 ออเดอร์
- แผนทางเลือก 20 ชุดผ่านข้อจำกัดเวลาและสูตรค่าส่ง
- แก้ไขข้อมูลแล้วแผนฉบับร่างหมดอายุ ยืนยันแผนเก่าไม่ได้
- ยืนยันซ้ำไม่สร้างงานเพิ่ม ออเดอร์ที่ยืนยันแล้วแก้ไขไม่ได้
- ใบงานใช้ข้อมูลลูกค้าสำเนา และแผนของวันก่อนหน้าไม่ล็อกงานวันนี้
- ทดลองผ่านเบราว์เซอร์จริง: เพิ่ม/แก้ไข/ยกเลิกออเดอร์ เพิ่ม/แก้ไข/ค้นหา/ลบลูกค้า เลือกแผน ยืนยันแผน ค้นหาใบงาน และตรวจหน้าจอมือถือ
